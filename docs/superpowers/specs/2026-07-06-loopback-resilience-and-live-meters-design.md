# Устойчивый захват собеседника + живые тайлы уровня записи

**Дата:** 2026-07-06
**Версия релиза:** 0.6.2 → 0.6.3
**Затрагивает:** `core/src/wasapi_recorder.rs`, `core/src/recorder.rs`,
`src-tauri/src/commands.rs`, `src/App.tsx`, `src/api.ts`, `src/types.ts`,
новый `src/components/RecordingMonitor.tsx`, `src/App.css`.

## Проблема

1. **Баг записи собеседника.** При 24-минутном разговоре звук собеседника
   (`system.wav`, WASAPI loopback) присутствует в начале, а после какого-то
   момента пропадает полностью — при том что собеседник **говорил всё время**.
   Значит это не тишина: loopback-поток заглох или дефолтное render-устройство
   сменилось под нами (типично для звонков: у Windows отдельный
   «communications»-дефолт, наушники/Bluetooth перекидывают endpoint).
   Текущий `capture_loop` (`core/src/wasapi_recorder.rs`) пишет в WAV только
   реально пришедшие байты: нет ни заполнения тишиной, ни детекта смены
   устройства, ни переоткрытия потока. Итог: `system.wav` перестаёт расти, а
   так как таймстемпов нет — весь последующий звук ещё и сдвигается относительно
   `mic.wav`.

2. **Нет обратной связи во время записи.** В основном окне при записи пусто.
   Пользователь не видит, идёт ли захват каждой дорожки, и узнаёт о потере звука
   только после расшифровки.

## Цели

- Собеседник не должен «пропадать»: захват восстанавливается после сбоя, а
  дорожки остаются синхронными по времени.
- Во время записи в основном окне — два тайла с бегущей волной (осциллограф)
  уровня: «🎙 Вы» и «🔊 Собеседник». Видно историю ~8 секунд; если дорожка
  замолкает — линия видимо выравнивается в ноль + мягкое предупреждение.

## Не-цели (YAGNI)

- Не трогаем event-режим микрофона (он работает).
- Не добавляем выбор устройства в UI, не переписываем сегментную запись
  (`mic.partN.wav`) — silence-fill работает по одному сегменту.
- Не делаем полноценный спектр/FFT — только уровень (peak) на дорожку.

## Часть 1 — Устойчивый loopback (`core/src/wasapi_recorder.rs`)

Три слоя защиты, независимые от точной причины сбоя.

### 1.1 Заполнение тишиной по стенным часам (обе дорожки)

Каждый `capture_loop` отслеживает «ожидаемое число сэмплов» =
`elapsed_wall_clock.as_secs_f64() × SAMPLE_RATE`. После записи пришедших сэмплов,
если фактически записано меньше ожидаемого больше чем на порог (например, 1600
сэмплов ≈ 100 мс), дописываем нули до ожидаемого.

- `elapsed` считается через `std::time::Instant`, зафиксированный при `start_stream`
  (в Rust `Instant::now()` доступен — ограничение на время касается только
  JS-workflow-скриптов, не крейта).
- Эффект: `mic.wav` и `system.wav` оба имеют длину, равную стенному времени →
  **всегда синхронны**; заглох loopback превращается в тишину-на-месте, а не в
  сдвиг всего хвоста.
- Применяется к **обеим** дорожкам (мик тоже подравнивается к стенным часам —
  гарантирует равную длину дорожек для `merge_tracks`).

### 1.2 Watchdog заглохшего потока + переоткрытие (loopback)

- Вынести настройку потока в helper
  `open_capture_stream(source) -> AppResult<StreamHandles>`, где `StreamHandles`
  = `{ audio_client, capture_client, h_event }`. Текущая инициализация
  (строки ~147–200) переезжает в него без изменения логики.
- В цикле хранить `last_data_at: Instant`, обновляемый при каждом **непустом**
  чтении. Если для loopback прошло больше `STALL_SECS` (2 с) без данных, пока
  идёт запись:
  1. `dlog(... "loopback stalled — reopening")`,
  2. `stop_stream()` + drop старых хендлов,
  3. `open_capture_stream(Source::Loopback)` заново (берёт **текущее** дефолтное
     render-устройство — восстановление после смены устройства/инвалидации/
     communications-дефолта),
  4. `start_stream()`, продолжаем писать в **тот же** `writer`. Пробел закрыт
     silence-fill из 1.1.
- Микрофон watchdog не переоткрывает (Capture-путь стабилен), но получает
  silence-fill.

### 1.3 Не-фатальные ошибки чтения (loopback)

- Сейчас `read_from_device_to_deque(...)?` пробрасывает любую ошибку →
  завершает поток → `stop()` падает (`sys_res?`).
- Для loopback: ловим ошибку чтения, логируем, направляем в тот же путь
  переоткрытия (1.2). Счётчик подряд идущих неудач; после `MAX_REOPEN_FAILS`
  (например, 5) — сдаёмся, логируем `loopback giving up`, дописываем тишину до
  конца и корректно финализируем WAV (дорожка остаётся читаемой и синхронной).
- Микрофон: поведение прежнее (ошибка фатальна — как и было).

### Диагностика/лог

Существующий итоговый лог (`reads/events_ok/samples/peak`) сохраняется.
Добавляются строки при событиях: `loopback stalled — reopening (gap=Ns)`,
`loopback reopened ok`, `loopback giving up after N fails`, и счётчик
`silence_filled=<samples>` в итоговой строке.

## Часть 2 — Живые тайлы уровня (бегущая волна)

### 2.1 Считывание уровня в бэкенде (core остаётся без Tauri)

- `WasapiRecorder` держит `mic_level: Arc<AtomicU32>` и
  `system_level: Arc<AtomicU32>`. В `capture_loop` при каждом чтении обновляем
  соответствующий атомик **пиком** чанка через fetch-max (нормализация до
  0..1000: `peak_i16.abs() * 1000 / 32767`).
- Новый метод трейта `Recorder`:
  ```rust
  struct TrackLevels { mic: u32, system: u32 } // 0..1000
  fn levels(&self) -> TrackLevels;
  ```
  Реализация `WasapiRecorder::levels` делает `swap(0)` на атомиках (peak с
  прошлого опроса → «peak since last poll»). Не пишет — читает-и-сбрасывает.
- `MockRecorder::levels` возвращает мягко осциллирующие фейковые уровни (по
  внутреннему счётчику), чтобы тайлы **разрабатывались и превьюились локально
  без Windows-бэкенда**. `is_recording()==false` → `{0,0}`.
- Новая Tauri-команда `recording_levels() -> TrackLevels` в `commands.rs`
  (читает состояние рекордера в `AppState`). Если не идёт запись — `{0,0}`.

### 2.2 Фронтенд

- `src/types.ts`: `TrackLevels { mic: number; system: number }`.
- `src/api.ts`: `recordingLevels: () => inv<TrackLevels>("recording_levels")`.
- `src/components/RecordingMonitor.tsx`:
  - props: `levels: TrackLevels`, `solo: boolean`, `elapsed: number`.
  - два тайла (в solo — только «🎙 Вы», собеседник для solo не пишется).
  - каждый тайл держит **фиксированный кольцевой буфер** истории уровней
    (~8 с при опросе 60 мс ≈ 130 столбцов) в `useRef`, обновляемый при смене
    `levels`.
  - рендер бегущей волны — inline **SVG** (полоски/полилиния), новые значения
    справа, старые уползают влево. Перцептивная шкала `Math.sqrt(v/1000)` — чтобы
    речь выглядела живо.
  - индикаторы: `● запись` (пульс `recpulse`); если уровень дорожки ниже порога
    несколько секунд подряд — мягкое `⚠ тишина N сек` (информативно, не ошибка).
  - Цвета из токенов Auris: «Вы» — `--brand-grad`; «Собеседник» — `--teal`/
    `--violet`. Никаких новых шрифтов/цветов вне дизайн-системы.
- `src/App.tsx`:
  - состояние `levels`, `setLevels`.
  - `useEffect`: пока `recording && !paused`, `setInterval(~60ms)` опрашивает
    `api.recordingLevels()` → `setLevels`; очистка интервала при остановке/паузе;
    на паузе уровни замирают (как таймер).
  - В `<main className="content">`: если `recording` — рендерим
    `<RecordingMonitor .../>` **вместо** `MeetingView`/пустого экрана (монитор
    приоритетнее выбранной встречи, пока идёт запись).
- `src/App.css`: стили тайлов (`.rec-monitor`, `.rec-tile`, `.rec-wave` и т.п.)
  в существующей дизайн-системе; переиспользовать `recpulse`; SVG-волна без
  бесконечных ripple-анимаций (чтобы скриншот-инструмент не таймаутил).

### 2.3 Тесты

- Vitest `src/test/RecordingMonitor.test.tsx`: подаём массив уровней →
  проверяем, что рендерятся два тайла (или один в solo), что при нулевом уровне
  появляется предупреждение «тишина», что история ограничена буфером.
- Бэкенд-путь (`levels`, `recording_levels`, silence-fill, watchdog) — покрыт
  компиляцией CI (`check-app`) + рантайм-тест пользователя на Windows.
- Юнит на `MockRecorder::levels` в `core` (возвращает ненулевые осциллирующие
  значения при записи, нули при простое) — гоняется в `cargo test -p uxo-core`.

## Потоки данных

```
запись идёт
  ├─ capture_loop(Mic)      → mic.part{N}.wav   + mic_level (fetch-max)
  │     └─ silence-fill по стенным часам
  └─ capture_loop(Loopback) → system.part{N}.wav + system_level (fetch-max)
        ├─ silence-fill по стенным часам
        └─ watchdog: заглох >2с → reopen на текущем render-устройстве

фронтенд (каждые ~60мс while recording)
  invoke recording_levels → {mic, system} (0..1000, peak since last poll)
     └─ RecordingMonitor: push в кольцевой буфер → бегущая SVG-волна
        └─ near-zero N сек → «⚠ тишина N сек»
```

## Риски и как их снимаем

- **Нельзя собрать/протестировать Rust локально** → компиляция через CI;
  корректность WASAPI (silence-fill, watchdog, reopen) — рантайм-тест
  пользователя на Windows (проиграть 24-мин звонок со сменой устройства/паузами).
- **Переоткрытие может зациклиться** при мёртвом устройстве → ограничено
  `MAX_REOPEN_FAILS`, дальше — тишина до конца + корректная финализация.
- **Опрос 60 мс = ~16 invoke/с** → дёшево для Tauri; интервал чистится на
  паузе/остановке.
- **Локальное превью без бэкенда**: `MockRecorder::levels` даёт данные, но в
  чистом vite-dev `invoke` недоступен — тайлы тестируем vitest'ом с инъекцией
  уровней и превью с замоканным `api`.

- `npx tsc --noEmit`, `npm test`, `npm run build` — зелёные локально.
- CI (`ci.yml`) зелёный: `frontend`, `core`, `check-app`.
- Версия 0.6.3 синхронно в `package.json` + `src-tauri/tauri.conf.json`.

  синхронны, в расшифровке собеседник не пропадает.
